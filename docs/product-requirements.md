# Coupon Mall 产品需求设计文档

版本：V1.0 评审稿  
编制日期：2026年11月23日  
面向：产品、设计、Java 后端、微信小程序前端、测试及运营团队  
状态：可用于拆分任务；平台权限、存量系统清单及经营资质确认后冻结上线范围。

## 1 产品背景与决策摘要

用户在淘宝、抖音看到的商品标价、券额和直播宣传通常分散在不同位置，难以确认适用规格、使用条件及真实购买成本。Coupon Mall 将截图识别、已授权优惠发现及同规格比价整合为“提交商品—确认条件—比较方案—前往平台”的闭环。

MVP 推荐采用微信小程序与 Java 模块化后端，先接通一个已获授权的数据渠道，再扩展第二个平台。全网优惠券雷达是产品愿景，首版对外应写“已接入渠道优惠”，不得宣称覆盖全部商家、全部优惠或实时全网最低价。截图识别是信息整理工具，不等同于核验优惠仍可领取。

本文中的数值为拟定产品默认值和验收目标，均不是现有系统实测结果或平台服务承诺。原对话中的价格示例和项目创意不作为真实平台能力证据。

## 2 目标与成功标准

1. 用户提交截图或商品链接后，可以理解优惠条件与价格组成。
2. 用户可以在同一规格、数量和购买条件下比较已接入渠道的候选报价。
3. 每个价格都有来源、采集时间和适用条件；未知条件显式展示。
4. 数据授权失效时仍能使用截图整理，停止显示失去依据的购买推荐。

首批灰度观察两周，不设虚构商业收益承诺。建议技术门槛：有效任务成功率≥95%，OCR 流程端到端 P95≤15秒；有缓存的列表 API P95≤800毫秒。依赖外部接口的任务允许异步返回。业务目标在灰度基线后确定，包括识别完成率、确认率、有效外跳率和价格争议率。

## 3 用户与场景

|角色|触发情境|期望结果|
|---|---|---|
|临时购买者|复制商品分享文本|查到当前可验证优惠及购买入口|
|直播观众|上传券或商品截图|提取门槛、截止时间并确认对应商品|
|谨慎消费者|比较淘宝与抖音同型号商品|看到同规格总成本和信息缺口|
|持续关注者|收藏目标商品|回看最新报价；后续授权订阅降价提醒|
|运营人员|渠道数据异常或用户投诉|停用报价、查看证据并纠错|
|管理员|平台授权到期|关闭渠道、更新配置、保留审计|

游客可浏览公共报价；上传按匿名会话限额使用；收藏与历史同步需登录。个人截图与识别结果仅本人可见，不直接进入公共雷达。

## 4 范围与非目标

P0：截图与文本输入、异步 OCR、规则确认、单渠道授权报价、受控商品库搜索、同规格比价、收藏、来源展示、合规外跳、后台纠错及渠道开关。

P1：第二渠道正式接入、价格趋势、明确授权的提醒、运营专题、更多品类属性模板。P2：经批准的购物车组合优化及更广渠道。

不包含代领券、代支付、订单履约、自动购买、账号托管、绕过登录或反爬、直播间实时抓券、未经授权抓取及个人补贴保证。首版不做跨店凑单、不支持把返佣直接减为到手价、不根据佣金高低修改默认比价排序。不建设自营商城交易链路。

## 5 业务流程与状态

### 5.1 截图识别

用户主动上传图片并确认用途 → 服务端校验文件 → 创建任务 → OCR 与规则结构化 → 展示字段与原图证据 → 用户修正商品、SKU、日期及券条件 → 查询授权渠道 → 计算方案 → 展示结果。

任务状态：CREATED → PROCESSING → NEED_CONFIRMATION → COMPLETED；校验失败为 REJECTED，处理失败为 FAILED，超时为 TIMEOUT。失败重试创建同一任务的尝试记录；重复客户端提交由幂等键返回原任务。截图只有券、没有商品时允许保存私有券笔记，不强行关联商品。

### 5.2 链接与搜索

主动粘贴文本 → 仅解析受支持平台域名及分享格式 → 通过已授权解析渠道查商品 → 缺失 SKU 时要求选择 → 查询报价与券 → 按统一上下文计算。解析不可用时提示改用截图或关键词，不上传用户 Cookie，不自动访问任意 URL。

### 5.3 雷达与购买

计划任务读取渠道授权及配额 → 拉取许可范围内数据 → 幂等入库、过期检查、规则校验 → 发布可用报价。用户点击购买 → 检查报价有效性并尝试刷新 → 有变化先展示新价格 → 用户再次确认 → 生成批准的推广或购买目标。仅记录外跳发起；没有合法订单回传时不推断成交。

### 5.4 比价

解析品牌型号及属性 → 产生候选 → SKU 严格匹配 → 统一数量、地区、会员条件和运费 → 排除过期及不可比项 → 计算含运费预估价 → 排序并展示依据。不足两条可比报价时展示单条报价及“暂无足够可比结果”。

## 7 页面与交互说明

全局底栏：首页、雷达、收藏、我的。AI 找优惠为首页主入口。字体和颜色不作为唯一状态提示；价格单位与条件不折叠在难发现位置。

|页面|主要信息和操作|状态与交互|
|---|---|---|
|首页|截图上传、粘贴框、关键词、已接入渠道|未读取剪贴板前由用户点击；无渠道时突出截图整理|
|AI 找优惠|隐私提示、上传预览、任务进度|后台处理中可离开；返回恢复任务；超时重试|
|识别确认|原图、证据高亮、字段表单|低置信字段标黄并文字提示；关键缺失阻止确认价格|
|雷达|搜索、平台筛选、报价卡片|空结果给出原因；渠道失败显示部分结果及失败渠道|
|商品详情|规格、数量、来源、券条件、价格组成|换规格重新计算；旧请求结果不得覆盖新选择|
|比价结果|对比口径、可比报价、条件差异|默认按可验证预估总价升序；同价按新鲜度；广告单列标注|
|收藏|最新价格与失效状态|支持取消收藏；不把失效券显示为当前可用|
|我的|登录、识别历史、隐私、删除、反馈|注销与删除有二次确认；不要求平台账号密码|
|运营后台|来源健康、报价审核、投诉队列|角色控制；批量操作确认；所有修改留审计|

价格主文案：“预估到手价 ¥X”；条件不全时：“参考价 ¥X，运费或资格待确认”。按钮分别为“查看领券方式”“前往平台”，不得把外跳发起描述为已领取。禁止默认勾选会员、新客身份和消息订阅。

## 8 优惠与价格规则

### 8.1 数据表示

金额统一使用人民币分的整数，币种单独存储。折扣使用有理数或 BigDecimal；中间过程保留精度，按有证据的平台舍入规则执行。未知舍入规则标记估算，展示至分，不宣称与结算一致。数量为正整数；MVP 同一 SKU，数量1至99。

券字段至少包含类型、满额门槛、减免金额或折扣、封顶额、适用商品及 SKU、适用人群、领取区间、使用区间、叠加组、门槛计算基数、来源和核验时间。未知字段不是零或无限制。

### 8.2 门槛与叠加

满100减20在基数恰为100元时满足。基数是否包含运费、商品折扣前后金额及其他券抵扣，由渠道规则确定；不能确认则不得进入确定价格计算。同一互斥组至多选择一张。跨组只有已明确允许叠加时才组合；未知关系按不自动叠加处理，并告知“叠加待确认”。

规则引擎通过规则版本确定折扣顺序；不得固定假定平台券、店铺券、品类券均可叠加。券选择在首版限定单 SKU 已验证组合；组合超限或规则缺失时降级为分别展示方案。优惠总额不能超过可抵扣商品金额，不产生负数。

### 8.3 有效期

内部存 UTC，展示 Asia/Shanghai；展示精度与来源一致。建议内部使用[start,end)半开区间；来源仅给“当日23:59”而未提供秒级定义时保留原文与时间精度，临界一分钟要求刷新，不自行补成已验证秒值。领取期限与使用期限分别判断。截图“今天”“今晚”没有拍摄日期时必须由用户确认日期，上传日不能代替截图日期。

活动未开始、已过期、领完、资格未知、不可用分别展示。来源冲突时不覆盖为可用；记录冲突并停止推荐。个人截图上的有效券也不能证明其他用户可领。

### 8.4 到手价

预估应付总额 = 选定SKU单价×数量 − 经规则验证的商品优惠 − 经验证可叠加券与满减 + 运费 + 已知必选费用。返佣、积分未来抵扣、赠品标价不抵减。新客、会员、支付工具补贴只能作为显式条件方案；资格未知不进入默认最低价。订阅费用不默认为零，须单独展示。

示例：单价120元，已验证商品直降10元，店铺券满100减20以直降后金额计门槛，运费5元，则预估95元。若平台10元券与店铺券互斥，分别为95与105元，推荐95元；不能展示85元。若直降后90元，则满100券不满足。

运费未知时只显示“券后商品价”，不参与含运费最低排序。用户选择地区到省市即可；不收集收货详细地址。缺货、预售定金、二手、跨境税费未知、组合装数量不一致均从严格同款排名排除。

### 8.5 比价与可信度

严格同款至少核对品牌、型号、容量或尺寸、颜色对功能的影响、套装件数、新旧状态、销售区域版本及保修条件。商品标题与图片相似只能生成候选。型号或关键属性冲突直接排除。容量可换算单价用于“相似规格参考”，但不得并入同款最低总价。

分别记录识别置信度、商品匹配置信度、来源核验状态和新鲜度，不合成伪精确的总分。建议模型字段置信度≥0.90且校验通过可预填，0.70至0.90提示确认，低于0.70标未知；金额与日期仍展示给用户检查。阈值需在标注集校准，模型自报概率不是可靠准确率。

价格可信状态：已授权来源核验、用户确认截图、未核验线索、过期。截图无论模型多自信都不能提升为官方核验。建议列表快照超过15分钟标陈旧；购买前重新查询，超过24小时且无法刷新不提供价格推荐。该时效仅为内部展示策略，实际刷新频率必须服从平台配额，不能承诺15分钟内覆盖全库。

## 9 数据来源与合规接入

截至编制日核查到淘宝官方文档存在 SKU 维度优惠券相关 API 文档；这只证明文档存在，不证明本项目可调用、可检索全部商品、可生成推广链接或可跨端分发。抖音官方资料表明能力与主体、场景和申请权限相关；生活服务商品接口不能用来证明抖音实物电商全库查询能力。

|来源|拟用数据|当前证据状态|上线前必须验证|
|---|---|---|---|
|淘宝联盟及淘宝开放平台|许可范围的商品、SKU、券和推广目标|有官方文档；本项目权限待验证|主体资格、AppKey、授权范围、配额、字段、推广位、展示和缓存期限、转链权限|
|抖音电商及获准联盟渠道|许可商品、优惠和导购目标|本项目全库检索、券查询、转链均待验证|具体平台入口、准入协议、应用权限、授权主体、可服务商品范围及跨端导流|
|用户上传|截图文字、个人规则笔记|产品设计可实现；供应商处理合同待定|用户告知、处理地区、第三方模型保留策略、删除链路|
|授权商家或服务商|签约商品与活动|未指定供应商|授权链、数据权属、更新SLA、转授权、终止后的删除|

不能把抖音开放平台、抖店开放平台、精选联盟与生活服务权限视为同一套权限。第三方声称“全网接口”不构成授权证明；缺少来源授权链不得入生产。不得模拟用户登录、购买 Cookie、抓私人券、绕过验证码或用未授权爬虫补足覆盖。

微信小程序向淘宝、抖音的唤起、跳转、口令复制、二维码及推广展示分别做真机和平台规则验证；没有获得批准的路径就隐藏对应购买按钮，提供条件说明，不承诺能跨平台直接购买。截图识别与合法数据展示可以独立保留。隐私政策、资质及广告导购披露由法务和平台审核确认，本文件不替代法律意见。

每个渠道建立能力登记表：能力、文档URL、应用ID、授权主体、审核截图、范围、测试请求ID、配额、有效期、负责人。只有权限和真实返回值都验证通过才能打开生产开关。

## 10 架构建议与复用策略

先盘点现有登录、用户、商品、收藏、对象存储、OCR、模型网关、调度、监控和后台。没有盘点证据前不假定现成能力存在；可以复用的模块必须验证接口、容量、成本、权限和维护人。记录“复用／适配／新增”结论后排期。

建议链路：微信小程序 → Java API → 识别编排／商品匹配／规则计算／报价查询／收藏模块 → 渠道适配器与OCR模型。MySQL 存交易无关业务数据，Redis 作短期缓存和限流，对象存储放私有原图。优先复用现有消息队列；没有时以数据库任务表与可重入工作进程实现首版异步，不为MVP强制引入微服务、搜索集群和向量数据库。

渠道统一接口定义 search、resolve、getOffers、buildOutboundTarget，均返回 capabilityUnsupported，不假定所有渠道实现全部方法。上游字段映射保留原始语义与映射版本。无网络调用的规则引擎基于快照计算，保存输入摘要、规则版本和结果以便重现。

任务采用租约、有限重试和死信状态；连接超时建议2秒，读超时5秒，最多2次指数退避，仅重试超时、限流等临时错误，不能重试无权限。参数按供应商SLA调整。缓存键包括平台、SKU、数量、地区、资格上下文和规则版本；禁止不同用户专属券共用缓存。敏感数据不进日志，凭证置于密钥管理服务。

## 11 核心数据模型

所有表带 id、created_at、updated_at；业务实体带 version，删除策略区分物理删除与审计保留。

|实体|关键字段|约束与关系|
|---|---|---|
|User|小程序主体标识、状态、同意版本|标识加密；不存淘宝抖音密码|
|RecognitionTask|user_id、input_id、status、attempt、error_code|用户隔离；幂等键唯一|
|RecognitionField|task_id、field、raw_value、normalized_value、bbox、confidence、confirmed_value|保留证据与人工修改|
|Product|brand、model、category、canonical_attributes|内部标准商品；不能用标题唯一去重|
|PlatformSku|platform、external_item_id、external_sku_id、product_id、attributes|平台与外部SKU联合唯一|
|Coupon|source_id、external_id、scope、threshold、benefit、time_windows、stack_group、eligibility|规则用带版本JSON；未知可空|
|OfferSnapshot|sku_id、price_fen、stock_state、freight、observed_at、source_id、expires_at|不可变快照；追加新版本|
|PricePlan|snapshot_ids、context_hash、rule_version、breakdown、total、confidence_state|能回放；总额未知可空|
|MatchCandidate|source_sku、target_sku、attribute_diff、status、model_version|严格匹配与相似参考分开|
|Favorite|user_id、sku_id|联合唯一|
|SourceCapability|source、capability、status、scope、quota、authorization_expiry|控制适配器与页面开关|
|Feedback及AuditLog|object_id、reason、evidence、operator、action|审计追加写；访问分权|

币种不一致禁止直接比较。上游ID按字符串保存。公共报价与用户私有券关联分表或强制访问域隔离；不得仅靠前端隐藏。

|POST /recognitions|uploadId或text、inputType|taskId、status|

|PATCH /recognitions/{id}/confirmation|version、confirmedFields|新version、缺失条件|

|POST /feedback|objectId、reason、description|feedbackId|

|GET /admin/sources|管理员身份|健康、权限到期、配额|

## 13 异常与风控

|异常或攻击|用户反馈|系统处理|
|---|---|---|
|模糊图、只有口号|识别不完整，可重传或补充|未知字段留空，不推测券额|
|提示词注入图片|正常识别信息|图片文字只作数据；模型不能执行指令或调用购买工具|
|恶意文件|文件不支持|校验真实MIME、解码、像素限制、恶意内容检测|
|任意URL及短链|链接暂不支持|域名白名单、每次重定向检查、禁内网地址、防SSRF|
|券已领完或过期|优惠不可用|撤下推荐并保留来源状态|
|授权撤销或配额耗尽|渠道暂不可用|熔断、告警、关闭外跳和陈旧价格推荐|
|模型超时|任务仍处理中或可重试|任务预算、重试上限；不重复扣用户额度|
|商品匹配有冲突|暂不能确认同款|转相似参考或人工反馈|
|点击时涨价|价格有变化|返回新明细，要求再次确认|
|批量薅接口|请求过于频繁|按用户、会话、IP组合限额，误伤可申诉|

建议初始限额为每账号每日20次识别、每分钟5次；游客每日3次；实际按成本和滥用数据调整。禁止通过采集设备敏感指纹实现风控。模型每日预算达到80%告警，达到100%停止新增识别并明确告知。

隐私默认：原图及供应商临时副本在任务结束后24小时内清理；用户选择保存的结构化历史保留30天，可提前删除；备份最迟30天轮转。以上为拟定内部政策，若供应商不支持必须更换或先修改并告知后再上线。删除主存储、缓存、对象和供应商副本需可追踪；审计保留期限由法务按必要性确定，不把截图永久写入审计。日志不记录完整图片、口令、访问令牌或原始个人分享文本。

## 14 埋点与指标

事件公共字段：event_id、匿名session_id、经授权的user_id、timestamp、app_version、page、request_id、source、experiment_id。服务端去重；金额按分；不得上传截图内容、完整链接、券口令及个人优惠资格明文。

|事件|触发|核心属性|
|---|---|---|
|input_submitted|创建任务成功|input_type、task_id|
|recognition_finished|任务终态|status、latency、missing_count|
|recognition_confirmed|保存人工确认|edited_field_count|
|offer_viewed|报价卡片有效曝光|offer_id、freshness_state|
|comparison_finished|服务端生成比价|comparable_count、excluded_count|
|outbound_started|批准目标生成并发起|offer_id、plan_id|
|outbound_failed|前端可观察失败|reason|
|favorite_changed|收藏状态变化|action|
|price_feedback_created|投诉成功|reason、plan_id|

识别完成率=完成识别任务数／合法已受理任务数；另报超时和低置信占比，不能剔除失败美化。确认率=已确认任务／进入待确认任务。有效外跳率=外跳发起的去重会话／有有效报价曝光的去重会话，不代表成交率。价格争议率=价格投诉去重方案数／已查看方案数，按渠道、SKU品类、新鲜度拆分。节省金额只在相同条件基准价可验证时计算；不能用划线价制造省钱指标。

## 16 验收标准与测试矩阵

每条 P0 需求需关联测试用例和负责人，以下为上线阻断条件。测试数据用授权样本或合成夹具，不使用未经许可采集的真实账号资料。

|编号|输入或场景|预期结果|
|---|---|---|
|A01|100元商品，满100减20，运费0|80元；99.99元不满足|
|A02|120直降10、满100减20、运费5|95元；明细与规则版本可回放|
|A03|20元店铺券与10元平台券互斥|比较两方案，不重复抵扣|
|A04|运费未知或会员资格未知|不标含运费最低；资格方案独立|

|A07|缺品牌型号或仅券截图|保存线索，不捏造商品关联|

|A15|渠道开关关闭及回滚|列表、详情、购买入口同步降级|

建立不少于200张经授权或合成标注截图的验收集，覆盖清晰、模糊、长图、相对日期、复杂叠加及无券图片。关键字段准确率按“金额、门槛、有效期、适用范围各自正确字段数／有真值字段数”分别统计；清晰样本目标≥95%，同时记录字段覆盖率，不能通过全部返回未知达标。无依据金额生成属于阻断缺陷；复杂未知条件必须提示确认。

性能在约定测试环境以并发50用户、持续15分钟验证列表与任务目标；OCR供应商限额计入条件并记录。合法受理任务终态成功率≥95%，崩溃、越权及可复现错误最低价为零。页面覆盖加载、空、部分失败、全失败、未登录、过期与低置信状态。上线前完成来源授权证据、隐私告知、平台审核和回滚开关检查。
